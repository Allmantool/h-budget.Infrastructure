# Role handoff contract

Every handoff must identify:

- change ID and authoritative requirement/spec revision;
- repository roots and candidate revisions or immutable diff/snapshot identifiers;
- owned paths and prohibited paths;
- applicable `AGENTS.md`, role, and skill instructions;
- safety, live-environment, financial-data, and scope constraints;
- commands, synthetic fixtures, and required checks;
- unresolved questions and checks already unavailable;
- expected result format, including PASS / FAIL / BLOCKED.

Requirements or architecture changes return to the owning stage. Evaluator and Tester receive requirements, the candidate, and evidence—not the implementer's hidden reasoning transcript.
